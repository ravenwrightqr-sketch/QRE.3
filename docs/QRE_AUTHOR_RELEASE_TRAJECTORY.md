# QRE Author Release Trajectory

## Release order

1. **Understand** the user input. Separate instructions from source material.
2. **Model** facts, people, places, time, memory, and the likely creative engine.
3. **Choose a trajectory** appropriate to the material: comedy, romance, horror, service transformation, memory, reveal, escalation, or another grounded structure.
4. **Author the sequence** with the local cinematic author. The author owns viewer-facing language.
5. **Compile a scene deck** of 4–8 distinct moments. Each scene must change, reveal, escalate, reframe, or pay off something.
6. **Studio** lets the user edit the sequence before playback.
7. **PLAY** enters a sealed cinematic player with no dashboard/debug/compiler language.
8. **Learn** from real usage after the author path is stable.

## Author rules

- An instruction such as `Create a video for my dog grooming business` is a brief, never a scene.
- Multiple supplied lines are separate sequence intentions; do not flatten them into one paragraph.
- Structured cognition is internal. Entity lists, provenance labels, parser fragments, and `+` token chunks never reach the player.
- Grounded memories preserve source facts; creative interpretation may use metaphor, personification, contrast, irony, rhythm, suspense, escalation, and emotional implication.
- Sparse creative briefs may be realized as generalized/fictional creative concepts, but must not invent specific customer facts as if they are true.
- The final scene should earn the ending rather than explain it.

## Minimum release acceptance

A prompt is release-ready when:

- it never appears verbatim as the cinematic scene unless the user explicitly supplied that sentence as scene material;
- the output contains at least 3 meaningful sequence moments when the author is available;
- each moment is distinct enough to feel temporal rather than like a paragraph split at arbitrary points;
- the scene deck contains no internal compiler terminology;
- the player can move through scenes automatically with timing and soundtrack behavior;
- user edits in the pre-play studio replace the viewer-facing scene text;
- if the local author fails, deterministic compiler scenes remain available as a safe fallback.

## Product loop

`prompt → cognition → trajectory → cinematic author → sequence → studio → play → behavioral learning`

Do not optimize the dashboard before this loop is reliable. The movie is the product; the dashboard is the instrument used to create and manage it.
